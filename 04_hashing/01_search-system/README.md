# Search System / Поисковая система

## Условие

Даны документы и поисковые запросы. Для каждого запроса нужно вывести до пяти самых релевантных документов.

Релевантность документа — сумма вхождений уникальных слов запроса в этот документ. Документы сортируются по убыванию релевантности, а при равенстве — по возрастанию номера документа.

## Формат ввода

Первая строка содержит число `n` — количество документов.

Следующие `n` строк содержат тексты документов.

Далее дана строка с числом `m` — количеством запросов.

Следующие `m` строк содержат поисковые запросы.

## Формат вывода

Для каждого запроса вывести номера не более пяти самых релевантных документов.

Документы с релевантностью `0` выводить не нужно.

## Ограничения

* `1 ≤ n ≤ 10^4`
* `1 ≤ m ≤ 10^4`
* длина одного документа не превосходит `1000`
* длина одного запроса не превосходит `100`
* документы и запросы состоят из строчных латинских слов
* в этой задаче разрешено использовать стандартные хеш-таблицы

```txt
-- ОПИСАНИЕ --
Реализована поисковая система для определения наиболее релевантных
документов по заданному запросу.

Для всех документов предварительно строится общий поисковый индекс -
для каждого слова хранится список документов, в которых оно встречается,
и число его вхождений. Далее, для каждого запроса вычисляется релевантность
документов (сумма вхождений уникальных слов из запроса) и выводится до 5
документов с наибольшим значением.

-- ПРИНЦИП РАБОТЫ --
Алгоритм состоит из двух этапов:

1. Построение индекса (WordIndex)
Для каждого документа строка разбивается на слова, подсчитывается частота каждого
слова в документе, после чего в индекс unordered_map<string, vector<WordCountInDoc>>
добавляется информация: слово → (doc_id, count). Таким образом, индекс хранит только
те документы, в которых слово действительно встречается, что исключает необходимость
полного перебора всех документов при каждом запросе.

2. Обработка запроса
Строка запроса разбивается на уникальные слова, по которым выполняется поиск в индексе.
Если слово найдено, то для всех документов, где оно встречается, к их релевантности
прибавляется число его вхождений, в результате получается отображение (doc_id → суммарная релевантность).
Далее формируется вектор документов с положительной релевантностью (sum > 0),
сортируется по убыванию релевантности (при равенстве - по возрастанию doc_id),
после чего выводятся первые 5 документов.

-- ДОКАЗАТЕЛЬСТВО КОРРЕКТНОСТИ --
Для каждого уникального слова запроса из индекса берутся документы,
в которых оно встречается, и их релевантность увеличивается на число вхождений этого слова.
Поэтому для каждого документа итоговая релевантность равна сумме вхождений всех
уникальных слов запроса.

Повторы слов в запросе не учитываются, т.к. запрос переводится во множество
уникальных слов (unordered_set). Документы с нулевой релевантностью отбрасываются,
остальные сортируются по убыванию релевантности (при равенстве - по возрастанию doc_id)
и выводятся первые 5 документов, что соответствует условию задачи.

-- СПИСОК ОБОЗНАЧЕНИЙ --
n — кол-во документов,
m — кол-во запросов,
L — суммарное кол-во слов во всех документах,
k — кол-во уникальных слов в одном запросе,
R — кол-во документов с положительной релевантностью для данного запроса (R ≤ n).

-- ВРЕМЕННАЯ СЛОЖНОСТЬ --
Построение индекса: каждый документ один раз разбивается на слова и по ним считается частота,
после чего данные заносятся в индекс. Поэтому построение индекса занимает O(L).

Обработка одного запроса: для каждого из k уникальных слов перебираются только те документы из индекса,
в которых это слово встречается. В худшем случае каждое слово встречается во всех документах,
поэтому подсчет релевантности может занять O(k * n). Далее применяется std::partial_sort для
выбора первых 5 документов с наибольшей релевантностью, что занимает O(R log 5) = O(R),
в худшем случае R = n, получаем O(n).

ИТОГО: O(L + m * (k * n + n)) в худшем случае

-- ПРОСТРАНСТВЕННАЯ СЛОЖНОСТЬ --
Индекс хранит для каждого слова список документов, где оно встречается, и частоту вхождений.
Суммарно это O(L) памяти.

Дополнительно при обработке запроса хранится отображение doc_id → relevance и вектор результатов,
в худшем случае на O(R) элементов (не больше O(n)).

ИТОГО: O(L + n)
```
