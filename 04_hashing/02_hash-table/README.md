# Hash Table / Хеш-таблица

## Условие

Нужно реализовать хеш-таблицу для хранения пар `key → value` без использования готовых реализаций из стандартной библиотеки.

Таблица должна поддерживать операции `put`, `get` и `delete` в среднем за `O(1)`.

## Формат ввода

Первая строка содержит число `n` — количество запросов.

Следующие `n` строк содержат запросы одного из видов:

* `put key value` — добавить или обновить значение по ключу;
* `get key` — получить значение по ключу;
* `delete key` — удалить ключ и вернуть его значение.

## Формат вывода

Для каждого запроса `get` и `delete` вывести результат в отдельной строке.

Если ключ не найден, вывести `None`.

## Ограничения

* `1 ≤ n ≤ 10^6`
* ключи и значения по модулю не превосходят `10^9`
* ключи и значения могут быть отрицательными
* количество ключей в таблице не превосходит `10^5`
* нельзя использовать готовые реализации хеш-таблиц
* рехеширование реализовывать не требуется

```txt
-- ОПИСАНИЕ --
Реализована хеш-таблица для хранения зарплат сотрудников (key → value),
поддерживающая операции put/get/delete без использования std::unordered_map.
Коллизии разрешаются методом цепочек, каждая корзина хранит список пар (key, value).

-- ПРИНЦИП РАБОТЫ --
Таблица хранит BUCKET_COUNT = 200'003 корзин в виде std::vector<std::list<Node>>.
Число корзин выбрано порядка 2*10^5, т.к. по условию - количество ключей в хеш-таблице
не может превышать 10^5, соответственно, коэффициент заполнения таблицы будет ≤ 0.5.

Для ключа вычисляется индекс корзины idx = Hash(key), где Hash это простая арифметическая
функция O(1): умножение ключа и взятие остатка по модулю числа корзин.
Далее, все операции выполняются только в соответствующей цепочке buckets_[idx], в списке std::list<Node>,
где Node - пары (key, value) данной корзины.

Операции:
1) put key value:
   - ищется узел с key в buckets_[idx];
   - если найден - обновляется value;
   - иначе добавляется новый Node в список.

2) get key:
   - выполняется поиск key в buckets_[idx];
   - если найден - возвращается value, иначе None.

3) delete key:
   - выполняется поиск key в buckets_[idx];
   - если найден - значение возвращается и узел удаляется, иначе None.

-- ДОКАЗАТЕЛЬСТВО КОРРЕКТНОСТИ --
Hash(key) определяет единственную корзину idx, в которой могут находиться элементы
с данным ключом, т.к. все вставки выполняются только в buckets_[Hash(key)].
Операции get и delete перебирают именно эту корзину и:
- возвращают значение только при нахождении узла с точным совпадением key;
- put обновляет значение существующего ключа и не создаёт дубликатов;
- delete удаляет найденный узел, после чего ключ отсутствует в таблице.
Следовательно, поведение операций соответствует условию.

-- СПИСОК ОБОЗНАЧЕНИЙ --
n — кол-во команд,
M — кол-во корзин (BUCKET_COUNT),
L — кол-во элементов в одной корзине (длина цепочки),
size_ — текущее кол-во элементов в таблице (size_ ≤ 10^5),
alpha — коэффициент заполнения хеш-таблицы (size_ / M).

-- ВРЕМЕННАЯ СЛОЖНОСТЬ --
Hash вычисляется за O(1).
put/get/delete выполняются за O(L).
При равномерном распределении ключей средняя L = O(1), поэтому
операции выполняются в среднем за O(1).
Итого: в среднем: O(n), в худшем случае: O(n * L).

-- ПРОСТРАНСТВЕННАЯ СЛОЖНОСТЬ --
Под корзины выделяется O(M), под хранимые пары ключ–значение - O(size_).
Итого: O(M + size_)
```
